# 効果量・確率の対象変数設定 実装計画

## 目的と受入条件

- タイトルの一時的な「効果量・確率設定」ボタンから、ゲームの見た目に依存しない読みやすい設定画面を開閉できる。
- 「効果量」「確率」の別タブで、悪夢・夢の種を縦スクロール一覧に全件表示し、1件ずつ線で区切る。効果説明と各効果Resourceにある数値変数の名前・現在値を表示し、変数ごとに対象／対象外をラジオボタンで選べる。
- タブごとの保存ボタンで、選択結果を元のEnemyInfo/SeedInfo `.tres` に記録する。失敗時は理由を表示し、元データを壊さない。
- 効果基底クラスが保存された変数名をカプセル化し、実戦では選択済み変数だけ効果量または確率補正を適用する。
- E1・E2・オトギリソウの連鎖と、未設定Resourceの従来挙動を維持する。

## 調査できた現状

- Main Scene は `res://scene/main/main.tscn`、Godot 4.6系のGDScriptプロジェクト。Title は独立Sceneで `Title` の子に固定ボタンを追加できる。
- 悪夢の効果は `EnemyData._duplicate_skill()` で個体ごとに複製され、`EnemyEffectStack` が優先度順に実行する。
- 種の効果は `SeedInfo` から共有Resourceとして参照する経路がある。実戦補正のために共有定義を直接変更しない。
- 既存のデバッグパネルは `get_property_list()` で公開数値を列挙し、編集後に `ResourceSaver.save()` で元の `.tres` に保存している。
- `EnemyEffectValueCalculator.scale()` と `roll()` が現行補正を担当するが、呼ばない効果は補正されない。

## 設計上の仮定

- 各変数に「対象／対象外」の2択を設ける。確率の対象は0〜1の確率値として扱う数値に限定し、分母や回数などは誤選択を防ぐ。
- 保存先はプロジェクトの定義Resourceとする。ゲームの書き出し後は一時設定画面を使用しない想定。
- 効果量・確率の対象選択は別々に保存する。選択前のResourceは従来の補正方式を維持する。
- 隣接する悪夢が与える補正は胃袋内の種ブロックのサブ効果へ反映する。装備中のメイン効果には胃袋内の隣接元がない。

## 所有関係とデータの流れ

`Title` が固定の設定画面を所有する。設定画面は `EnemyInfo` と `SeedInfo` を一覧化し、子の `EnemyEffect` / `SeedEffect` の公開数値を列挙する。保存時には基底クラスが保持する対象変数名を更新して元の `.tres` へ保存する。保存失敗時はメモリ上の選択を戻す。実戦では個体効果または種ブロックの実行窓口が基底クラスの補正APIを使い、選択済み変数だけを計算対象にする。

## 失敗時の切り分け

- Resource保存失敗: パスが `res://` 内か、UID/参照を保ったまま保存できているかを確認する。
- 倍率の二重適用: 既存の `scale()` / `roll()` と選択済み変数の補正を同一効果で重複させていないかを確認する。
- 効果が変わらない: 効果の実行窓口を通るか、種ブロックの個体状態を参照しているかを確認する。
- 表示漏れ: `PROPERTY_USAGE_EDITOR` と `PROPERTY_USAGE_SCRIPT_VARIABLE`、数値型、除外プロパティを確認する。
